Meet Our Dataset

Train and test files merged into one har.csv: 561 features + subject (person id) + Activity (label).

Clean from the start: no missing values, no duplicates, and every feature already lies between -1 and 1.

Features… Do We Really Need All of Them?

High dimensionalityCurse of dimensionalityHighly correlated features

8,093 feature pairs correlate above 0.9. Many features repeat the same information, and in high dimensions distances become less meaningful, which hurts K-Means and DBSCAN.

Can we simplify the data without losing important information?

Preparing the data

Getting Ready to Cluster

Clustering is unsupervised, so the label is hidden from the algorithms and used only at the end to judge them.

Every experiment runs through the same two helpers, run_kmeans() and run_dbscan(), so the comparison is fair.

ARI · Adjusted Rand Index

How close the clusters are to the real activities. 1 = perfect, 0 = random. Higher is better.

Silhouette

How well separated the clusters are. Always computed on the original 561 scaled features, so a 2D method can’t look better just because it lives in 2D. For DBSCAN, noise points are left out.

Time

How long the clustering itself takes. Lower is better.

What is “UMAP (10) + K-Means”?

561 features→UMAP → 10 dimensions→K-Means, K = 6→6 clusters

UMAP first squeezes the 561 features into 10 new dimensions (the “10” is dimensions, not clusters). K-Means then groups those 10 numbers into 6 clusters.

K-Means on UMAP (10) vs real activities
