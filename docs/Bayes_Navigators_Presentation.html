2 · Algorithm Explanation

Naive Bayes is built on Bayes’ Theorem

A probabilistic classifier: for each class it calculates how likely that class is, given the features, and picks the most likely one.

P(Class | Features) = P(Features | Class) × P(Class) P(Features)

Prior

How common disruptions are in general, before we look at the shipment (61%).

Likelihood

How typical these features are for disrupted vs. normal shipments.

Posterior

The updated probability of disruption for this shipment. This is the answer.

Evidence

The same for every class, so we can ignore it when comparing classes.

2 · Algorithm Explanation

Why “Naive”, and how it works

The naive assumption

All features are independent of each other inside each class. This lets us simply multiply one-feature probabilities.

P(x1,…,xn | C) = P(x1|C) × P(x2|C) × … × P(xn|C)
1

Learn priors

Count how often each class appears in training data.

2

Learn likelihoods

For each feature and class, learn the distribution of values.

3

Multiply

For a new shipment: prior × all likelihoods, for every class (adding logs in practice).

4

Decide

Pick the class with the highest score.

2 · Algorithm Explanation

Types of Naive Bayes, and why we chose Gaussian

Our start

Gaussian NB

Bell-shaped likelihood. For continuous numbers.

Categorical NB

Frequency per category. For categories.

Multinomial NB

Counts. For text / word counts.

Bernoulli NB

Yes / No values. For binary features.

1

Our strongest signals are continuous numbers (risk score, reliability, fuel, distance).

2

It is the standard starting point (GaussianNB), very fast, and gives probabilities for risk scoring.

3

Our features are almost uncorrelated, so the naive independence assumption fits this data well.

!

But it assumes bell shapes. Our weather columns are 0/1. We will see this problem and fix it by switching to Categorical NB.

7 · Improving Naive Bayes

Why our final model is Categorical NB

Same algorithm and same Bayes’ theorem. Only one step changes: how we calculate P(feature | class).

Gaussian NB (our baseline)

Fits a bell curve

Our weather columns are only 0 or 1, so a bell curve does not describe them.

Hurricane never happens in “Normal” shipments, so its variance is 0. The curve becomes an infinitely thin spike and the math breaks.

Categorical NB (our final model)

Counts values

Simply counts how often each value appears in each class. Numbers are split into 5 bins first (risk 7.3 → “6–8”).

Laplace smoothing adds 1 to every count, so Hurricane in “Normal” becomes 0.0006 instead of 0. Small, but safe.

9 · Conclusion

Key insights

01

Baseline: precise, but misses a lot

Gaussian NB reached about 70% accuracy with high precision, but its recall was low and it missed many disruptions.

02

The cause: the wrong distribution

The 0/1 weather columns are not bell-shaped, and the Hurricane column had zero variance for one class.

03

The right distribution is the real fix

Tuning var_smoothing helped a little. Categorical and Mixed NB raised recall from about 0.58 to 0.80 and F1 from 0.71 to 0.79.

04

Simple can compete

The improved Naive Bayes ended within about 1 point of Logistic Regression and Random Forest, while being much faster than Random Forest and easier to explain.
